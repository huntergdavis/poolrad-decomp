# Resident 0802:0040, the character writer: raw CPU, composed with Dos.Intr (t30 display stack)

`pr_r0802_0040` (`src/recovered/resident_0802_0040_cpu.c`) is the raw-CPU, full-state model of START.EXE resident `0802:[0040,0105)`, the bottom of the t30
cluster's DISPLAY stack (0193 -> 0105/0175 -> 0040). It is the first body in the approved bottom-up order (VP i20338): 0105 and 0175 call it per character, 0193
calls those. Its only callee is `Dos.Intr` (`0A32:000B`, runtime-covered, #1259), so it composes real models with no unready stop.

**A body and its evidence; no credit is claimed here.** Identity follows the t30 chain ruling, through the role line below.

## Media span

| Body | Span | Bytes / insns | SHA-256 |
| --- | --- | ---: | --- |
| Character writer | `0802:[0040,0105)` | 197 / 72 | `371aba1b1f82444f7021284640b7eed635a7d0a9f97b25333fb9723071d798cd` |

The audit asserts that the decode covers the span exactly, the single return (`RETF 0Ah` at `0102`), the four `LCALL 0A32:000B` (at `0062`, `00A5`, `00D0`, `00FC`), no
call, interrupt or port instruction, the three jumps (`007D` -> `008F`, `008D` -> `0095`, `00AF` -> `0101`), and that **the four Intr segment words (`0065`, `00A8`, `00D3`, `00FF`)
are the only loader relocations in the span**.

## Behaviour

Five byte-valued arguments, each in a word slot (the high byte of every slot is stale and ignored): char, count, attribute index, row, column. `Regs` is the Dos-unit register
record at `DS:4A02` (AX at `4A02/03`, BX `4A04/05`, CX `4A06/07`, DX `4A08/09`, ...).

    0040 PUSH BP; MOV BP,SP
    0043 Regs.AH := 2 (set cursor); Regs.BH := [4A1B] (page); Regs.DH := row ([BP+0Ch]); Regs.DL := column ([BP+0Eh])
    005A PUSH AX (AL := 10h, AH as it stands); PUSH DS; PUSH 4A02h; LCALL 0A32:000B               Intr(10h, Regs)
    0067 Regs.AH := 9 (write char and attribute); Regs.AL := char; Regs.BH := [4A1B]
    0078 [4A1E] = 0:  Regs.BL := [25D5 + attr] (the attribute map)       else:  Regs.BL := attr
    0095 Regs.CX := count (zero-extended byte); PUSH 0010h; PUSH DS; PUSH 4A02h; LCALL 0A32:000B  Intr(10h, Regs)
    00AA [4A1E] = 1 ONLY:  the same pair again on page [4A1A], attribute untranslated (Regs.BL := attr)
    0101 POP BP; RETF 0Ah

### What DS:4A1E means (tested, not assumed): three behaviours, not two

| `DS:4A1E` | Attribute | Writes |
| --- | --- | --- |
| `0` | translated through the map at `DS:25D5` | **one**, on page `[4A1B]` (two INT 10h calls) |
| `1` | **not** translated | **two**: page `[4A1B]`, then page `[4A1A]` (four INT 10h calls) |
| anything else (`2`, `FFh`, ...) | **not** translated | **one**, on page `[4A1B]` (two INT 10h calls) |

So `2` is **not** the same as `1`: the translation test is `<> 0` and the second-page test is `= 1`. A flag read that way is a three-valued dispatch, and the fixtures run `0`, `1`, `2` and
`FFh` (`ega02-*` and `ega0xFF-*`), with the BIOS-live run on `0`, `1` and `2`. A mutant that treats `2` like `1` is caught.

The attribute map is exercised in full: the audit translates **all 256 attribute indices** with `DS:4A1E` = 0 (and the same 256 untranslated with `DS:4A1E` = 1), with a map whose entries are distinct
(`entry k = A0h + 7k + 3`), and 24 random cases use random maps.

## Composition and contract

- **Composed from its model on main:** Dos.Intr `0A32:000B` (`dos_intr_000b_cpu`), four times, each far-call segment word read live from the code. Each Intr call must return to the instruction after its call
  (`0067`, `00AA`, `00D5`, `0101`), otherwise the stop is **TRANSFER**.
- **Declared environment:** the INT 10h handler Intr transfers to (`dos_intr_000b_cpu.h`). It may write RAM; every operand after it is reread in source order.
- **Stops:** RETURNED; **INTR** (Intr did not return; the diagnostic names its status, `SERVICE` = the handler refused, and how many Intr calls completed); **TRANSFER**; ARGUMENT (nothing changed).
- Exactly 1 MiB of A20-off RAM, IP = `0040h`, entry SP in `[0022h,FFF0h]`. No flag is masked.

**Role line (t30 side i, direct game-state operands):** writes `count` copies of one character with an attribute at `row`,`column` on the display page(s) through INT 10h. It reads the game's display pages
`DS:4A1B` and `DS:4A1A`, the EGA flag `DS:4A1E` and the attribute map `DS:25D5`, and writes the Dos-unit register record `DS:4A02`.

## What each check pins (and what it cannot)

| Check | Claim it pins | Shares a mechanism with the thing it tests? |
| --- | --- | --- |
| **C test** (41 checks, ASan/UBSan) | the C model's contract on synthetic frames | yes: it is the model |
| **Independent contract** (Python, 660 cases) | the INT 10h register blocks the body issues, derived from the inputs only | no code with either model; but it is OUR statement of the contract |
| **Unicorn differential** (684 cases) | the C model equals the ORIGINAL body and ORIGINAL Intr bytes on 14 CPU words and all 1 MiB, with the INT 10h blocks logged into RAM by a real-byte stub | no: the oracle is the original bytes under Unicorn |
| **Native stub-level** (run A, 49 cases) | the same, under DOSBox-X instead of Unicorn | no, but **the INT 10h stub is ours on both sides**: a wrong belief about INT 10h would leave A green |
| **Native BIOS-live** (run B, 40 cases) | that the register blocks MEAN what we think: AH=02 page/row/column, AH=09 char/attribute/count, the translation only at `DS:4A1E` = 0, the second page only at 1 | **no: the mechanism is DOSBox-X's real INT 10h**, compared with an independent text-mode model |

Run B is the only check whose mechanism is not ours, and it is why it exists: the stub-level runs would stay green if our understanding of INT 10h were wrong. It is **not** a proof about the game's graphics path.
It runs the original bytes and the original Intr on DOSBox-X's real BIOS in **text mode 03h** (80x25, eight pages) and reads back the eight text pages (`B800:0000..7FFF`) and the BIOS cursor words
(`0040:0050..005F`). Limits, named: **text mode only** (the game's own display may be an EGA graphics mode, where the BIOS draws glyphs through the planes; that path is the EGA device of
the 0294 evidence and is not exercised here); **cases stay inside one row and pages 0..7**, so what the BIOS does past a row end or on an unsupported page is not claimed; and the BIOS is the packaged DOSBox-X's.

## Evidence

Receipt: 2026-10-21, branch from main `1336293f`.

**Unicorn: 684 cases, all RETURNED**, comparing unmasked CPU14 and all 1,048,576 RAM bytes with the whole loader-expanded image loaded at test base `1000` and the loader's own relocations applied (no byte patched):

- **body starts 72/72**, **Intr members 69/69** of the original Intr bytes, and the INT 10h stub's own 26/26 instructions (the closure by segment is `0802` 72, `0A32` 69, and 26 at the stub's test segment); **conditional outcomes 4/4** by successor
  (`007D` to `007F` and to `008F`, `00AF` to `00B1` and to `0101`);
- **Intr calls histogram:** 2 calls in 358 cases, 4 calls in 326, matching the `DS:4A1E` table above;
- **660 cases** whose logged INT 10h blocks (AX BX CX DX SI DI BP ES, in order) equal the independent contract; the other 24 alias the frame or the log, where the C model and the original are compared byte for byte;
- cases: the four `DS:4A1E` values x eight attributes; all 256 attributes with `DS:4A1E` 0 and 1; characters, counts (`0`, `1`, `2`, `28h`, `FFh`), rows and columns including `FFh` and `80`; page pairs (`0/0`, `7/3`, `3/7`, `FF/0`, `1/1`, `0/FF`); six flag images; random high bytes of the argument slots;
  random Regs, registers, flags and attribute maps; SP at `0022h`, `0023h`, `FFF0h` and odd; log counts `3`, `15` and `FFFFh` (the stub's index wraps); and aliases with the frame **over Regs** and **over the attribute map**.
- **Mutation check:** six deliberate changes to the model are each caught: the translation branch sense, the second-page test (`2` treated as `1`), the map index `+1`, `AH := 0Ah` for `9`, the first block on page `[4A1A]`, and the count masked.

**C test:** 41 checks pass under ASan/UBSan (`-Werror`).

**Native DOSBox-X** (packaged `dosbox-x` 2026.01.02, `core=normal`, `cputype=386`; the image relocated to `3000h` and read from `IMAGE.BIN` before every case, so each case starts from the original bytes):
