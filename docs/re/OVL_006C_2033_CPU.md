# Overlay unit `0x06C` display branch at `+2033`

`pr_ovl_006c_2033_cpu` models `GAME.OVR` unit `0x6C` `[2033,206E)`: **59 bytes /
23 instructions**, one far return `RETF 4` at `206B`, no interrupt, port or
direct game-memory write. Body SHA-256
`9d2095e546eea202d4fc5b9e42490735020536df5b63fe1e0dd6a85a715d9add`
(unit load segment `0078h`, unit code maps at offset 0, so the body runs at
`0078:2033`).

An earlier strategy note described the dependent of
[`RES_00BA:0973`](RES_00BA_0973_CPU.md) as "108 B / 42 instructions". Measured,
that is not this body: `108` is the gap from `+2033` to the next
prologue-scanned offset and `42` is what a disassembler emits for the whole gap,
whose last 19 bytes after the return are non-code. The body itself ends at
`RETF 4` on `206B`.

## Frame, branches and callees

The far call is Pascal: the frame holds two argument words and `RETF 4` consumes
them. `[bp+6]` is a **word offset in `SS`** used as a pointer, and `[bp+8]` is a
byte parameter.

| Site | Decoded action |
| --- | --- |
| `2033..2039` | Save `BP`, then compare the byte at `SS:([bp+6]-00Dh)` with `6`. |
| `203E..2051` | **Below 6**: load that byte and `[bp+8]` as words and far-call `0085:002F` (unit `0x77` entry 3). |
| `2053..2065` | **6 or above**: push `DS:[5D94]:[5D92]`, `x = 4`, `y = 012h` and `[bp+8]`, then far-call `00BA:0973`. |
| `206A..206E` | `pop bp`; `RETF 4`. |

The far-call operand bytes are checked by the model (`9A 2F 00 85 00` and
`9A 73 09 BA 00`), together with the compare, branch and return encodings, so a
different body cannot silently take this structure on trust.

### Declared boundary: `0085:002F`

The `0085:002F` target is unit `0x77` entry 3, a **331-byte / 129-instruction**
routine at unit `+0901`. It in turn calls `03F1:0137`, `00BA:1037`,
`0709:0626` and `0AF8:0B25/0B0B/0B98`; of those only `1037` and `0626` have
accepted models, and `03F1` is not one of the 34 overlay unit memory segments.
That chain is **out of scope** here and declared a boundary: the model pushes
exactly what the original pushed and returns `PR_U6C_2033_BOUNDARY` with
`CS:IP` at the call site (`0078:204C`) and the flags from the `CMP`. The
differential compares the oracle's state at that same call site, so the
hand-over is proven byte-for-byte; the callee's behaviour is not. Modelling the
chain is a separate step.

### Composed callee: `00BA:0973`

The `6 or above` branch composes the accepted
[`RES_00BA:0973`](RES_00BA_0973_CPU.md) model, which composes the accepted
`1037` formatter and `0709:0626` printer. The model pushes the five argument
words and the far return exactly as the original and then defers to that model;
`AL`, the final flags and the return frame are its results, after which the body
pops `BP` and returns 4 bytes. The active far pointer is read from
`DS:[5D94]:[5D92]` on every call, not cached.

## Evidence

`tools/overlay/ovl_006c_2033_cpu_audit.py` runs the **real original bytes**: the
expanded `START.EXE` image at load 0 (so `00BA:0973`, `1037`, `0709:0626` and
`0AF8` are the original code) and the hash-pinned `GAME.OVR` body. The candidate
side runs the C model with the C `0973`/`1037`/printer models. Compared per
case: all 14 CPU words, all RAM outside `A0000..AFFFF` (`983,040` bytes), the
ordered `OUT` events and the ordered `A0000` write operands.

Measured at this branch (`--unicorn`, 21 cases, 6 of them boundary cases):
`22/23` instruction starts, `2/2` conditional outcomes, `1,360` `OUT` events,
`2,560` `A0000` write operands. The one unvisited start is `2051`, the `JMP`
after the declared boundary call: with the `0x77` callee out of scope it is
**unreachable by construction**, and the audit fails if any other start is
unvisited. Three semantic mutants were killed by this audit in temporary copies
(threshold `6 -> 7`; using a constant instead of `[bp+8]`; dropping the
`CMP` flags).

`--compile-only` builds and binds the candidate library with no game media and
prints `CHECKER_BUILD_OK`.

## Registration and credit

The checker declares `CHECKER_ROWS = ('OVL_006C_2033',)` and
`checker_execution_profiles.json` lists that row with `observe: true`, so
agreement requires the `ROW_EXECUTED OVL_006C_2033 PASS` marker the audit emits
after all cases pass. The row is **not** in `docs/re/strict_full_c_addresses.csv`,
so registration adds no credit row and moves no accounting; `credit_evidence_kind.csv`
is unaffected.

**Ownership: unresolved.** This model assigns no authorship and makes no
game-versus-library claim.

## What this does not establish

- No native DOSBox execution, gameplay reachability or full-game behaviour.
- The `0085:002F` callee's semantics: it is a declared boundary, not a model.
- Relocated loads. The checked call operands are the load-zero fixups, and the
  contract is load-zero only.
- The differential runs a **relocated copy of the body at `7800h`** so it cannot
  overlap the resident image held at load 0; the body reads no `CS`-relative
  data, so this does not change its behaviour, but it is not a test of the
  loaded-segment value itself.
- Exhaustive input coverage: 21 adversarially chosen cases, not a domain proof.
- The composed `0973` contract's own limits (its entry-SP window, non-aliasing
  and load-zero-only terms) apply unchanged.
