# OVL_03B6_0000: 5 x 5 map window through the 3CEh tile stub (raw CPU, composed)

`pr_ovl03b6_0000_cpu` is a raw-CPU, full-state model of GAME.OVR unit `3B6h` entry 1, `+0000`. It draws a 5 x 5 window
of the 44-column tile map `DS:3648`, applying up to nine override records. All 25 tile calls go through overlay stub
`03E9:002A`, which is unit `3CEh` entry 2, `+00F1`, and they compose [OVL_03CE_00F1](OVL_03CE_00F1_CPU.md)'s model,
which in turn composes `RES_0464_08D4`'s.

**Claim.** `OVL_03B6_0000` is the credit target. `OVL_03CE_00F1` is evidence and readiness only. `RES_0464_08D4` is
**uncredited** (`unresolved` in the resident ledger; evidence PR #1413,
[RES_0464_COMPOSE_08D4_CPU.md](RES_0464_COMPOSE_08D4_CPU.md)). Identity is the PM's call. The facts are in the
[claim table](#claim-table).

## Behaviour

The arguments are `[BP+6]`, the row origin, and `[BP+8]`, the column origin (words).

For row `r` (`[BP-8]`, 0..4) and column `k` (`[BP-7]`, 0..4):

1. `x` := low byte of `k + [BP+8]` (`[BP-4]`), and `y` := low byte of `r + [BP+6]` (`[BP-5]`).
2. `tile` := `DS:[3648 + y * 2Ch + x] − 1` (`[BP-6]`). `x` and `y` are sign-extended, and the product and the sum wrap
   at 16 bits.
3. For each record `i` = 1..9 (`[BP-3]`): if the words `DS:0C30 + 6i` and `DS:0C32 + 6i` equal `x` and `y`, the record
   matches. The byte is sign-extended to 32 bits (`CWD`) and compared with the zero-extended word, so a negative
   coordinate never matches. On a match, records 3..9 replace the tile with the low byte of `DS:0C34 + 6i` minus 1,
   gated by the window-0 words at far `DS:49D2`:

   | Record | Replaces when |
   | --- | --- |
   | 1, 2 | never |
   | 3 | `+318h` ≠ `00FFh` |
   | 4 | unless `+3A4h` = 0, `(+2F8h AND 8)` = 0 and `+33Eh` ≠ 0 |
   | 5 | `(+340h AND 2)` = 0 |
   | 6 | always |
   | 7 | `(+340h AND 1)` = 0 |
   | 8, 9 | `+366h` > `00FDh` (unsigned) |

   Later records override earlier ones. The record index is the dispatch selector; the gates read game state.
4. Call the stub with the frame (1 in AL, `tile`, `[BP-2]`, `[BP-1]`). `[BP-1]` starts at 0 for each row and steps by 3
   per column; `[BP-2]` starts at 0 and steps by 3 per row. AH of each byte word is whatever the preceding instruction
   left.

**The stub.** It is executed as on the CPU. A resident unit's entry holds `JMP FAR` (`EAh`) to the unit's
segment:`00F1`, which is what the overlay manager writes. The model follows it into `00F1`, whose `RETF 8` returns
straight to this body. An unloaded entry (`INT 3Fh`) stops with `OVERLAY` before the overlay manager runs; the CPU is
then at the stub with the call frame pushed.

**Statuses.** `OK`, `ARGUMENT`, `CALLEE` (`00F1` stopped; the diagnostic gives the site, `00F1`'s status and its
diagnostic), `TRANSFER`, `LIMIT` (this body's own backward jumps) and `OVERLAY`.

**Undefined flags.** The `MUL DX` at `0043` and sixteen `SHL DI,1` leave flags undefined. The emitter's report shows
each one is overwritten on every path before any read, branch or stop.

## Claim table

These are facts checked against the original bytes. **Identity is the PM's call.**

- **Factor 1, the callers.** The queue at `6fac2396` finds four fixup-backed far calls through stub `03CD:0025`, and
  no near caller. Each caller pushes `[BP+8]` first, then `[BP+6]`:

  | Caller | Site | Origin pushed (column, row) |
  | --- | --- | --- |
  | unit `3B4h` `+016D` | `0293` | locals `[BP-1]`, `[BP-2]` (sign-extended bytes; `[BP-2]` clamped to `0..1Fh` just before) |
  | unit `75h` `+06B3` | `06CA` | constants `11h`, `0Fh` |
  | unit `75h` `+06B3` | `07D9` | the words `DS:094D[2n]`, `DS:095F[2n]` (`n` = byte `[BP-2]`) |
  | unit `75h` `+06B3` | `08DC` | constants `17h`, `19h` |

  The same function, `75h:+06B3`, also calls `0464:1E5C` with the tile set at `DS:5E52/5E54`, the pointer `00F1`
  reads.
- **Factor 2, what the body itself reads.**
  - **The map `DS:3648`, 44 columns:** [U68_TILE_STEP_0818.md](U68_TILE_STEP_0818.md) decodes `OVL_0068_0818`. That
    body reads the same table with the same arithmetic, `tile := DS[0x3648 + (y * 0x2C + cbw(col)) mod 65536]`, and
    tests the tile before a move. [U33_GRID_DRIVER_11B4.md](U33_GRID_DRIVER_11B4.md) also reads the `2Ch`-stride table
    at `DS:3648`.
  - **The window-0 block at far `DS:49D2`:** [ECL_STORE_WORD_84E8.md](ECL_STORE_WORD_84E8.md) shows the ECL store
    routine writing window-0 words through `[0x49D2]`. U68 `+0818` reads the window-0 position words `+186h`/`+188h`
    through the same pointer. This body reads `+2F8h`, `+318h`, `+33Eh`, `+340h`, `+366h` and `+3A4h`, the record
    gates.
  - **The records `DS:0C30 + 6i`:** no doc names this table yet. The gates above decide which records apply.
- **The dispatch selector** is the record index `i` (the loop counter), not data. The data it gates is the window-0 block.

## Validation

**Focused C test.** `test_overlay_u3b6_window_0000_cpu.c` passes **22** hand-predicted checks under CTest, built with
asserts on (no `CMAKE_BUILD_TYPE`, no `NDEBUG`). It uses synthetic RAM with no game bytes:

- `00F1` direct: the high set with tile `05h` from `85h`, and the low set with `7Fh`. It checks the `08D4` frames left
  below SP, both return addresses and the `RETF 8`.
- The window at (3, 2): 25 calls, the last cell's high-set tile, the screen coordinates (12, 12), the locals and the
  `RETF 4`.
- Record 6 replaces the last cell; record 3 gated by `+318h = 00FFh` does not.
- `OVERLAY` at an unloaded stub, with the frame pushed; `LIMIT` at the first backward jump (`01C9`).
- `08D4`'s own `LIMIT` propagated as `00F1` `CALLEE`, then `03B6` `CALLEE`; the argument checks.

**Unicorn differential.** `tools/overlay/ovl03b6_0000_cpu_audit.py --unicorn` runs the original closure: this body, the
loaded stub, `00F1`, `08D4` and SYSTEM `Move`. It reuses `ovl040c_015d_cpu_audit.py`'s image, fixture and runner with
unit `3CEh`'s code in place of `40Ch`'s. It adds unit `3B6h` at `5200h`, the stub entry, the map, the records, the
window-0 block at `5400:0000`, and both tile sets written explicitly. It compares all 14 CPU words and the whole 1 MiB,
with **no mask**, and requires that neither side raises an interrupt, a port access or an environment event.

| Measure | Result |
| --- | --- |
| Cases | **92** (76 enter `03B6`, 16 enter `00F1` directly) |
| Stops | 91 `RETURN`, 1 `OVERLAY` |
| `03B6` starts / branch outcomes | 211/211, 42/42 |
| `00F1` starts / branch outcomes | 38/38, 2/2 |
| Composed tile calls | 1,892 |

The cases cover:

- origins at zero, far, at the signed wrap (`7Dh`), negative and with garbage high bytes;
- maps of only high tiles and only low tiles;
- records 1–9 matched, each gate on both sides, x-only and y-only matches, negative coordinates, tile words 0 and
  `1234h`, three records overriding one cell, and all nine at once;
- video modes 0–3, wide tile sets, relocated unit segments and the unloaded stub;
- the flag seeds, and 30 random origins, records, window-0 words, register seeds and fill bytes.

**DOSBox-X.** `--native` uses `ovl040c_015d_cpu_native.py`'s oracle, which far-jumps to the case's CS:IP with
interrupts off. It adds the stub segment's first 40h bytes, which hold the loaded entry, to the compared regions.
**60** cases (44 enter `03B6`, 16 enter `00F1`) all `RETURN` and match with **no flag masks**. Each compares CPU14 and
303,168 bytes of RAM in six physical windows:

**Unicorn-only cases** (32; not counted as natively compared):

- **The unloaded stub:** it executes `INT 3Fh`, the overlay manager's interrupt, which the bare oracle does not install.
- **The relocated unit segments** (`9800h`/`9A00h`): both units sit outside the oracle's loaded regions.
- **The 30 random cases:** as for 015D and 03F1, their writes are not shown to stay inside the loaded regions, and a
  stray store hangs DOSBox.
- All four video modes do run natively: `08D4` writes only its destination object and the DS metadata.
