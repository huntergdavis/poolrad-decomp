# OVL_0023_0239: append a picked item to the active character's item list (raw CPU, composed)

`pr_u23_append_0239_cpu` is a raw-CPU, full-state model of GAME.OVR unit `23h` `+0239`.

**This PR is a body and its evidence; no credit is claimed here, and identity is the PM's.** The body, audit, native
harness, mutation driver and C test were written by par-d (retired); the PM pushed them as
`claude/par-d-ovl-0023-0239-body` (`a2c28ba7`). This PR brings that work up to date with main (by merge, unchanged)
and adds this document with the evidence run on the merged tree. The Claude lane did not rewrite the code.

## Behaviour

**Frame.** The routine is entered by a far call. `[SP+4]` is the RESULT far pointer, and `[SP+8]` is the ITEM far
pointer, which points to a 63-byte (3Fh) record. DS:[5D92] is the far pointer to the active character record. The
character's `+C8h/+CAh` holds the head of its list of 63-byte records, each linked at `+2Ah/+2Ch`.

1. **Capacity check.** 275B is called with the character and ITEM, reached through overlay stub `0085:004D`, whose
   loaded `JMP FAR` is a declared substitution checked as `RESOLVE`.
   - If AL is non-zero, the 10-character literal at `CS:022E` is loaded into a local by `0AF8:0B0B` (StrLoad) and
     displayed by `00BA:1693`. Then `*RESULT := 1` and the routine returns, with no append and no `0BB8`.
2. **Append.** Otherwise `*RESULT := 0`.
   - **Empty list:** `GetMem(3Fh)`, `Move(ITEM, node, 3Fh)`, `node.next := nil`, `head := node`.
   - **Non-empty list:** walk to the tail, then `GetMem`, `Move`, `new.next := nil`, `tail.next := new`.
3. **Finish.** `00BA:0BB8` is called on the character, then `RETF 8`.

**Statuses.**

- `OK`.
- `ARGUMENT`.
- `CODE`: a call site isn't in its original form.
- `RESOLVE`: the stub doesn't resolve to 275B.
- `CALLEE`: a composed callee stopped; the diagnostic gives the call index and the callee's raw status.
- `TRANSFER`.
- `LIMIT`: the list walk took more backward jumps than `walk_limit`.

The full contract is in `overlay_u23_append_0239_cpu.h`.

**Composed callees.** Every callee runs through its merged model:

- the 275B capacity check (`overlay_0077_275b_cpu`, composing 0BB8 and 13AB);
- StrLoad `0B0B`;
- display `00BA:1693`, with the EGA;
- GetMem `023F`, with its heap walk;
- Move `0A3F`;
- `00BA:0BB8`.

- **`walk-zero-offset-link`:** a list link whose offset word is 0000 but whose segment is not. The walk ORs both words,

- **Call-site and stub stop cases now enter with FLAGS 08D7h.** At the default SP, `SUB SP,14h` produces all-clear

**Unicorn-only cases.** These are not counted as natively compared:

- **GetMem failure, two cases:** SYSTEM RunError `0AF8:00E2` runs Halt's exit chain, which a bare oracle cannot survive.
  The first run hung DOSBox and wrote a 4.9 GB log, now deleted.
- **SP `0201h`:** the oracle always enters with SP at its own stack top, so a case with a different SP could never
  compare.
- **Entry flags with IF set:** the oracle's `POPF` would enable interrupts inside the body, and a timer IRQ frame
  (`F000:FEAF`) would land in its locals. IF is cleared in every native case's flags.

## Claim table

**Identity is the PM's call.** These are the facts, each checked against the original bytes (GAME.OVR units `23h`
and `20h`).

- **Factor 1, the callers.** There are exactly three, found by the audit's asserted segment-wide census (`ownership()`):
  - two near `PUSH CS; CALL 0239` sites in `23:0361`, at `23:03DE` and `23:0427`;
  - one fixup-backed far call through the unit's stub, `0028:002A` (public entry 2), at `20:0C60` in `20:0C06`.
- **Factor 2, the arguments.**
  - **ITEM:** every caller passes its local far pointer `[BP-4]:[BP-2]`. Each caller first sets it to nil (`23:0367..036C`,
    `20:0C0C..0C11`), then passes its address to a picker:
    - `23:0030`, called at `23:0396`;
    - `20:0B14`, called at `20:0C3B`.
  - **Each picker** (`RETF 10h`) receives four far pointers: the key byte `[BP-5]` (`[BP-9]` in `20:0C06`), the item
    pointer `[BP-4]`, the list-node slot `[BP-13h]` (`[BP-0Eh]`), and a word (`[BP-15h]`, `[BP-10h]`).
    - It calls overlay stub `03C5:0034` with that slot's address, among other arguments (`23:01B2..01C4`,
      `20:0BCF..0BE1`).
    - It stores the returned AL into the caller's key byte (`23:01C9..01CC`, `20:0BE6..0BE9`).
    - It copies the far pointer now in the slot into the caller's item pointer (`23:01CF..01DF`, `20:0BEC..0BFC`).
  - **The list head:** each caller initialises the slot from DS:[6810] (`23:036F..0379`, `20:0C14..0C1E`) before calling
    the picker. So ITEM is a node of the DS:[6810] list, the one the slot holds when the menu returns.
  - **The key gate:** `23:0361` calls 0239 only when the picked key is `42h` ('B') or Enter (`23:0399..039D`). `20:0C06`
    calls it only when the key is `54h` ('T') or Enter (`20:0C3E..0C48`).
  - **RESULT:** each caller passes a local byte, `SS:[BP-0Fh]` (`SS:[BP-11h]` in `20:0C06`).
- **What the DS:[6810] list is.** It is a list of 63-byte records linked at `+2Ah/+2Ch`. ECL CLEARMONSTERS frees exactly
  this list, `3Fh` bytes per node ([U1C_CLEARMONSTERS_125D.md](U1C_CLEARMONSTERS_125D.md)).
- **What this body does.** It appends a copy of ITEM, with its links cleared, to the active character's own 63-byte
  record list:
  - the active character is DS:[5D92] → `+C8h/+CAh`, the `.ITM` sidecar list (see
    [RESIDENT_SIDECAR_APPEND.md](RESIDENT_SIDECAR_APPEND.md) and [../formats/DOS_CHARACTER.md](../formats/DOS_CHARACTER.md));
  - the append happens unless the capacity check 275B refuses. A refusal shows the over-capacity message instead.
- **Role line (proposed):** copies the record the player picked from the DS:[6810] list (key 'B' or Enter in `23:0361`,
  'T' or Enter in `20:0C06`) onto the end of the active character's item list, unless the 275B capacity check refuses it,
  in which case it shows the over-capacity message and sets RESULT.
