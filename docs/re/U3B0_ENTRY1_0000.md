## Original identity and behavior

| Item | Measured value |
| --- | --- |
| DOS v1.3 `GAME.OVR` | 206,105 bytes; SHA-256 `872964a32cef0fc32bbf83bab68b15e04ad36d59076f37b00a179dfee7928614` |
| U3B0 entry 1 | runtime stub segment `0x3C5`; file `[0x2C8CF,0x2C936)`; unit `[+0x0000,+0x0067)` |
| Original body | **103 bytes / 38 instructions**, SHA-256 `a7d25485edf131a638e320475f22544c82fe81967478369e17556db2509b2a3c` |
| End | `RETF 6` at `+0x0064`; next prologue `+0x0067` |
| Calls | none inside this body; ledger reports five far and six near incoming references |

The caller supplies a far head pointer at `[BP+6/+8]` and a 16-bit count at
`[BP+0x0A]`. The function walks that many next pointers through each
node's far pointer at `ES:[DI+0x2A/+0x2C]`, stopping early on a null
pointer. It returns the selected far pointer in DX:AX if the requested count
was reached, otherwise `0000:0000`. Count zero returns the head, including
a null head. Its stack locals and full far return are part of the model.

The six local near call instructions are at `+0x07DE`, `+0x097F`,
`+0x0A1E`, `+0x0B39`, `+0x0BC4`, and `+0x1089`. These are static
call sites, not proof of gameplay reach. The existing entry6 node allocator
creates nodes with the same next-pointer layout, but its unresolved GetMem
effects are not imported into this leaf.
