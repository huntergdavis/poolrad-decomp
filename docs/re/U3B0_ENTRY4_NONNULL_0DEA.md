# U3B0 entry4 `+0DEA`: non-null pre-caller prefix

`src/recovered/overlay_u3b0_entry4_nonnull_0dea.c` executes the
original DOS v1.3 `GAME.OVR` non-null branch from `+0DEA` through
`+0DFE`. It stops at `IP=+0DFF`, before the separately reviewed
node-count caller prefix. Its input frame is generated by both
original SYSTEM `0AF8:0B25` copies and the original taken `+0DC7`
node-head gate. No copy output, branch result, or caller frame is
fabricated.

The pre-implementation `deja "poolrad U3B0 entry4 +0DEA +0DFF
non-null node head second copy successor C flags ownership"` query
found no matching prior session. Local and remote ownership scans
found no U3B0 source for `[+0DEA,+0DFF)`; the `+0DFF` caller slice is
separately owned by commit
`f4c9e515f1d7408be2597e496a4f343bb98106cb`. The two-copy
predecessor address lead came from the disjoint local `+0DC7` gate
head `c8f5b8479947f3f401e3c0fed5bed825301b0f9b`; this
non-null slice was independently checked against original bytes.

| SYSTEM copy body | `START.EXE [0xB79B,0xB7BF)`; 36 bytes; SHA-256 `009955722e8f73d0a0f7076aa418d141f642c5a729b2a58dfa7a7a3922989118` |
| Stop boundary | `+0DFF` begins the existing `PUSH [BP+0x16]`, `PUSH [BP+0x14]`, `PUSH CS`, `CALL +0067` caller sequence |

The prefix writes byte `1` to `DS:[0x6B2B]`, sign-extends byte
`SS:[BP+0x1E]` into DX and byte `SS:[BP+0x1A]` into AX, computes
`AX = second - first + 1` with original `SUB` and `INC` flag effects,
and writes AL to `SS:[BP-0x54]`. It does not execute the node-count
call or any later entry4 side effect.

The oracle starts at entry4 `+0D9A`, executes both original SYSTEM
copies and the original non-null branch gate, and captures every RAM
byte and CPU word at `+0DEA`. It then runs original `+0DEA..+0DFE`
and C from that same frame. **48/48** controlled cases match full
1 MiB RAM and all 14 CPU words at `+0DFF`. Cases vary SP, both
Pascal string lengths including the 40-byte cap, offset-only and
segment-only non-null heads, and signed byte pairs including AL wrap.
Both copy output buffers, DS restoration, and returned SP are checked.

  -DCMAKE_EXE_LINKER_FLAGS='-fsanitize=address,undefined'
