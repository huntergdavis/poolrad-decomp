# OVL_0025 +0341: translated, evidenced LOAD-block wrapper (evidence only; no credit proposed)

This raw CPU body, `OVL_0025_0341` (unit 0x25, entry slot 4), clears a 1E00h-byte caller buffer, shows a prompt row, builds a file name from the digit at `DS:[5376]`, loads a block by id through `0802:0716`, copies the
block minus its two-byte header into the buffer and frees the block. It is the wrapper whose only unwritten body was the 208-byte span below. This change adds the model, its checker, its native harness and this document. It
proposes **no strict row, no identity row and no manifest row**; par-e accepts or refuses.

## What the body does

Frame after the far call: `[SP]` IP, `[SP+2]` CS, `[SP+4]` the block id (a word slot, read as a byte at `[BP+6]`). `RETF 2`.

1. `PUSH BP; MOV BP,SP; SUB SP,112h`.
2. `FillChar(DS:[49DE]^, 1E00h, 0)` (`LES DI,[49DEh]`, then the far call `16A8`); `DS:[557C] := 0`.
3. Retry loop at 035F: row clear (stub `03C5:002F`, unit 0x3B0 +06FB); a message `StrLoad` (`cs:0322` into `[BP-22h]`) and print at (0, 18h) colour 0Fh; `Str(DS:[5376], M=1)` into `[BP-6]`; name `StrLoad` (`cs:0338` into
   `[BP-10Ch]`); `StrCat`; extension `StrLoad` (`cs:033C` into `[BP-111h]`); `0802:0716(id, &size [BP-8], &block [BP-0Ch])`; `CMP size,2; JB 035F`.
4. `Move(size-2, block+2, DS:[49DE]^)`; `FreeMem(block, size)`; row clear; `MOV SP,BP; POP BP; RETF 2`.

## The stub 03C5:002F, declared exactly

The row clear is a real, fixup-backed far call whose segment word reads **03C5**, unit 0x3B0's run-time stub segment; the offset **002F = 20h + 5 x 3** is entry 3, which is `+06FB` (22 bytes, SHA-256 `b306a980ebf183c4dd57a62414c019d47d68787e6f6577d61da8bec63e9fc09b`, fixup at 070D).
As in the 0EC4 and 0411 documents: **the INT 3Fh overlay-manager dispatch is not executed**; the five bytes become a far JMP (`EA lo hi seg`) to the loaded span, identically in the oracle and the C model. The C model reads the stub segment word
live and requires `EA` plus the offset (else CODE, IP at the call, before its return frame). **Unit 0x3B0's `memory_segment_sequential_ok` is False**: it is the first unit after a descriptor gap, and its segment is derived from the next
descriptor, corroborated by the live call word. **What this pins:** the call frames and what 06FB does with them. **What it does not pin:** the manager, stub construction, or residency of unit 0x3B0.

## Pointer census (every pointer the body dereferences that it did not create)

The VP's standing requirement. "Bus" means the access goes through `pr_bus` (so it can reach the A0000..AFFFF aperture, where a plane read is not the flat byte).

| Pointer | Source | The body's own access | Bus? | Who touches the pointee |
| --- | --- | --- | --- | --- |
| `DS:[49DE]` (far pointer variable, the buffer) | a DS global, caller state | reads its two words (`LES`, twice) | **no: flat DS access** (same class as the stack and code accesses) | FillChar and Move, both flat SYSTEM models; **the body never dereferences the pointee itself** |
| `DS:[5376]` (digit), `DS:[557C]` (flag byte) | DS globals | read / write one byte | no, flat DS | none |
| the block id `[BP+6]` | the caller's frame | one byte read | no, flat SS | none |
| `&size [BP-8]`, `&block [BP-0Ch]` | the body's own frame (created here) | written by 0716, read back by the body | no, flat SS | 0716 |
| the block pointer | **created by 0716** (a GetMem block) | handed to Move (as block+2) and FreeMem; never dereferenced by the body | n/a | Move, FreeMem |
| string slots `[BP-22h]`, `[BP-6]`, `[BP-10Ch]`, `[BP-111h]`, and `cs:0322/0338/033C` | stack and code | passed to StrLoad/Str/StrCat/Print | no, flat | the string and print models |

So the body itself dereferences **no caller-supplied pointee**: its only caller-supplied pointer is the buffer pointer, which it reads (flat, from DS) and passes on. The 0411 defect class (a wrapper dereferencing a handed pointer through flat RAM
where the machine goes through the aperture) therefore cannot occur in this body's own accesses; the same exposure sits one level down, in FillChar and Move, whose contracts are flat RAM and which are shared SYSTEM models with their own documents.
**Declared limit:** a buffer pointer into the A0000..AFFFF aperture is outside FillChar's and Move's flat contract. `--demo` constructs it on purpose (buffer at `A000:0100`): the model returns, the original returns, CPU14 agrees, and **7,680 RAM
bytes plus the EGA state differ** (first at 0xA0100). That is a demonstration of the contract limit, not a differential case, and nothing here claims otherwise.

### Adversarial fixtures (a caller-supplied pointer placed inside a block the body returns or frees)

- **`buf-inside-block`**: the buffer `DS:[49DE]` is aimed at `3000:0100`, inside the first heap allocation, which is the block 0716 returns and FreeMem frees. FillChar clears 1E00h bytes of it before the load; the load then fills the
  block; Move copies the block into the buffer overlapping its own source; FreeMem frees the region that holds the destination. The differential is the pass condition (CPU14, all 1 MiB, EGA, files, logs equal), and the independent statement reads the buffer from the pointer
  last used, not from a precomputed one.
- **`buf-inside-block-low`**: the buffer starts at the block's first byte (`3000:0000`), so Move copies the block over itself shifted by two.
- Both run with `alias=True`, which skips the precomputed buffer-contents statement (the destination overlaps the source) and keeps the differential and the call-sequence statement.
- The original receipt did not exercise the pointer **variable** `DS:[49DE]` inside the returned block. The directed follow-up below closes that synthetic fixture gap and checks the pointer re-read at 03E7.

### The retry loop

`CMP size,2; JB 035F` repeats while the loaded size is below 2, and the loop has **no key wait**. The model has a fresh budget per entry and stops LIMIT at IP 03DC with the JB not executed. The audit compares the original at the **same arrival** (the
budget+1'th arrival at 03DC with CF=1), and records what the original's state does between arrivals:

| Case | Arrivals | CPU identical at every arrival | RAM per arrival (class index) |
| --- | --- | --- | --- |
| `retry-id-missing` (budget 3) | 4 | yes | `[0,1,1,1]`: **fixed point from arrival 2** (asserted) |
| `retry-budget-5` (id missing) | 6 | yes | `[0,1,1,1,1,1]`: fixed point (asserted) |
| `retry-size-0` | 4 | yes | `[0,1,2,3]`: **not a fixed point**; 3 bytes of low RAM (0x3D, 0x40, 0x41) change per pass |
| `retry-size-1` | 4 | **no** | `[0,1,2,3]`: not a fixed point |
| `retry-budget-0`, `retry-budget-1` | 1, 2 | | too few arrivals to classify |

**Correction to my own earlier expectation:** I had expected every retry case to be a fixed point and the audit asserted it; `retry-size-0` failed that assertion. The assertion now applies only to the id-missing cases, where nothing is allocated per pass.
For a loaded size of 0 or 1 each pass advances heap state, so **the original is not shown to hang**: whether it ends in a heap-exhaustion RunError after enough passes was **not measured**. The model's LIMIT is a host cap: for id-missing the original provably repeats forever (fixed point, no key wait); for sizes 0 and 1 the cap is a bound on a loop whose end was not measured.

### Which way verdicts move under a convention split

- **`LES` straddle (physically contiguous in Unicorn and the corpus, wrapped in the pinned DOSBox-X):** the body's two `LES` sources are `DS:[49DE]` and `[BP-0Ch]`, neither of which can sit at offset FFFFh (the DS global is at 49DEh; BP is at least 09ECh). **No case depends on the convention, so no verdict moves.**
  This is a property of these two addresses, not a measurement on a wrapping CPU.
- **Buffer offset FFFFh and F000h (`buf-offset-ff`, `buf-wrap`):** FillChar and Move walk the buffer by 16-bit increments in both runs; both oracles agree. A CPU that did not wrap would move these two cases (and no others) from pass to mismatch; none was run.
- **The aperture:** a buffer in A0000..AFFFF moves the verdict from pass to fail on a machine where plane reads differ from flat bytes (the `--demo` result above); no differential case places it there.

## t109: the pointer variable inside the returned block

**Corrected claim:** the dormant `bufptr_in_block` setup assumed that the first
heap allocation was the block returned by 0716. It is the **packed buffer**;
0716 allocates its returned block afterwards. Enabling the dormant setup did
not establish the intended pointer redirection: the original and C reached
matching end states, but the expected redirected-buffer check failed.

The new `bufptr-in-returned-block` case accounts for both allocations and
asserts the actual source block and destination from the original Move call
frame. The synthetic archive contains a 32-byte block with an 11-byte packed
representation. The packed allocation rounds to 16 bytes, so the fixture starts
the heap at `2118:0000` and the returned block starts at `2119:0000`.
`DS:[49DE]` has physical address `2119E`, **14 bytes inside that returned
32-byte block**; all four bytes of the pointer cell lie inside it.

An additional original-only observation enables the existing oracle's call
capture for relocated segment `1802`. It records SYSTEM GetMem in this order:
**16 bytes, return `1802:0032`** (inside 0020), then **32 bytes, return
`1802:08CA`** (0716's own GetMem). The final packed-buffer pointer at `DS:557E`
is `2118:0000`. These are observed call frames, not C-model predictions.
Local receipt: `resources/u25-0341-bufptr-evidence/allocator-order.json`.
The heap address is computed from the encoded size and the pointer cell's
physical address; the fixture then checks the original's actual Move source
against that derived address.

The initial cell names `7A00:0000`, which FillChar clears. Decoding the block
overwrites the cell with `7C00:0000`. The original's Move frame at 03F3 names
the new destination and copies **30 bytes**, the block minus its two-byte
