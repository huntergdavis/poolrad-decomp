# Resident 0802:0716, the ECL/DAX block loader: raw CPU, composed, with named seams (t30)

`pr_r0802_0716` (`src/recovered/resident_0802_0716_cpu.c`) is the raw-CPU, full-state model of START.EXE resident
`0802:[0716,094A)`. That is the game's block loader for the ECL*.DAX archives, and the entry of the t30 `RES_0802` cluster:
all 21 endpoint-free rows reach the cluster through it.

**This PR is a body and its evidence. It is not a credit.** The body's 7 near-call sites into the cluster are named stops until
those leaves land. When they do, this body's differential is re-run with the real leaves composed at the seams and reported
as an updated receipt (VP i20311). Only then is a strict/identity row proposed for acceptance.

## Composition: this body's only unknowns are its 7 near-call sites

Of the 23 far calls, **22 go to SYSTEM models already on main**:

- StrStore `0B25` ×2, string load `0B0B` ×2, concat `0B98` ×2;
- BlockRead `14FB` ×5, IOCheck `04A9` ×7;
- Str `1366`, FilePos `1593`, GetMem `023F`, Seek `1563`.

The 23rd goes to the **credited** `0899:0000` (Quit).

The model composes every SYSTEM model:

- Each far-call segment word is read live from the code, so the loader relocations hold.
- Each callee must return to the instruction after its call; otherwise the stop is **CALLEE**.
- IOCheck's and GetMem's jumps to `0AF8:00E2` are the terminal **RUNERROR**.
- BlockRead's recsize-0 DIV is **DIVIDE**. It is unreachable here, because 05CD resets both files with recsize 1.
- A declared DOS service that breaks its contract is **SERVICE**.

**QUIT is a terminal stop with the call executed.** The CPU is at the credited body's entry. Composing Quit itself would bring
in the whole 08AE driver environment, and Quit never returns.

The 7 near-call sites (`05CD`, `0193`, `06E7` ×2, `0020`, `050F`, `0000`; the audit pins this exact set from the decode) are entered by `PUSH CS; CALL` and return by `RETF`.
Each is a **named stop** with the call executed: CS and the return IP are pushed, and IP is the callee. The model resumes at
the return IP from the post-callee state. The resume entries are 0778h, 084Dh, 08B0h, 08BFh, 0920h, 0938h and 0944h.

**Contract.**

- Exactly 1 MiB of A20-off RAM holding the relocated image. The SYSTEM models need their code at the original offsets; for
  example, Str's powers-of-ten table at `CS:12A6`.
- IP must be 0716h or a resume entry.
- Entry SP in `[0300h,FFEAh]`. The frame is 23Eh bytes, and the composed models' own frames lie below it.
- The declared DOS services are BlockRead's read and FilePos's/Seek's LSEEK, each under its own model's contract.
- GetMem's free-list walk is capped by `getmem_steps`.

| --- | ---: |

**Reading the table.**

- The decoded shape suggests the display stack matters. The profile says otherwise: **0193 is the rarest stop**, reached only
  on the over-limit prompt path.
- **05CD is the busiest, but it cannot be built first.** It tops a three-body chain: 05CD calls 025D, which calls 02EB and,
  when `[557C]` = 0, loops on 0193 (the "insert disk" prompt).

**The approved order is therefore bottom-up, not busiest-first:**

1. 06E7, composable today (Close + IOCheck);
2. 02EB, composable today;
3. 025D, whose audit must set `[557C]` = 0 so the prompt loop is exercised;
4. 05CD;
5. 050F;
6. 0000 and 0020 (resident_runtime);
7. 0193 last.

## How the t29 terminal declarations govern composition (VP i20320)

The t29 endpoint declarations are not bookkeeping; they decide the control flow of every body that composes them.

- **IOCheck is declared TERMINAL** on any non-zero InOutRes (its RunError at `0AF8:00E2`). So **06E7**'s
  Close → IOCheck → Close → IOCheck **cannot** continue past a failed first close: file A is left untouched. The four failure
  shapes are separate stops, not a sequence.
- **02EB is the converse.** It is compiled `{$I-}` and has no IOCheck, so a failed Reset flows on into Close and IOResult as
  data. That is why its absent-file answer is 103 (Close's), not 2 (Reset's).
- The same reading applies to 0716: each BlockRead/FilePos/Seek is followed by IOCheck, so any I/O error in the loader ends at
  RUNERROR at the first failing call.
- **Do not generalise from one body to another.** The cluster mixes `{$I+}` bodies (06E7, 0716: each I/O call is followed by
  a terminal IOCheck) with `{$I-}` bodies (02EB: failures fall through into the result flag). How each composes depends on
  which mode it has, so read each body's own bytes for an IOCheck before assuming either shape (VP i20322).

## Narrow values crossing wide boundaries (VP i20324, i20328)

**The rule, stated once:** in this cluster and the SYSTEM code it composes, a value is repeatedly narrower than the place it
lands, and the original keeps exactly the narrow part. A model that "respects the types" (a wide product, a word-sized flag,
a widened sum) is wrong at each such place. So read the width at every boundary from the bytes, and give the audit a case at
the wrap or truncation. The instances found so far, each pinned by its audit:

1. BlockRead `0AF8:14FB` keeps the low word of count·recsize ([SYSTEM_BLOCKREAD_14FB_CPU.md](SYSTEM_BLOCKREAD_14FB_CPU.md)).
2. Seek `0AF8:1563` truncates n·recsize to 32 bits from two 16-bit MULs ([SYSTEM_SEEK_1563_CPU.md](SYSTEM_SEEK_1563_CPU.md)).
3. StrStore cuts 02EB's and 025D's names at 40 characters ([RES_0802_02EB_CPU.md](RES_0802_02EB_CPU.md)).
4. 05CD passes 025D's flag as a byte in a word slot with a stale AH ([RES_0802_025D_CPU.md](RES_0802_025D_CPU.md)).
5. 05CD's header word is a 16-bit add in place (FFFEh → 0), zero-extended into Seek; a short read replaces only the bytes it
   got ([RES_0802_05CD_CPU.md](RES_0802_05CD_CPU.md)).
6. 050F's `in`, `out` and pointer offsets are 16-bit and wrap within their segments; the size test is unsigned
   ([RES_0802_050F_CPU.md](RES_0802_050F_CPU.md)).
7. 0020 rounds the size with a 16-bit `ADD 7` before `AND FFF8h`: FFF9h–FFFFh wrap to a 0-byte request, and GetMem answers
   nil with no RunError ([RES_0802_0020_CPU.md](RES_0802_0020_CPU.md)). 0000 does the same rounding before FreeMem, so a
   release of FFF9h–FFFFh bytes is a silent no-op, a leak with no pointer check ([RES_0802_0000_CPU.md](RES_0802_0000_CPU.md)).

New instances are added to this list, not as a new section per body. Instances 1 and 2 are in the SYSTEM unit, not in 0802.

**The related aliasing case is a different kind of fact, not a width.** The not-open path of the shared check (14B6, composed by
BlockRead, and its inline copies in Seek and FilePos) stores 103 into InOutRes at `DS:4426`. When SS = DS and the check's near-`RET` slot is that same word, the RET
goes to 0067h (**TRANSFER**). There is one slot, reached from two entry SPs: 442Ah for Seek and BlockRead, and 4428h for
FilePos, whose helper is entered without a `PUSH BP`.

## Prompt-path keyboard contract (025D audit, #1326)

Kept verbatim as the contract any later body that reaches 0193 must declare:

> AH=01h reports only type-ahead; AH=00h takes type-ahead first, else the next key; ReadKey 0059 waits and then drains.

The `typeahead-drained` case in `res0802_025d_cpu_audit.py` pins it. If a future body depends on the difference between a
pending key and a waited key, this sentence is the contract.

## Non-returning stops and LIMIT stops in the cluster (VP i20342)

A caller composing these bodies must treat every **non-returning** stop as terminal: the original never comes back. A
**LIMIT** stop says only that our declared budget ran out, and claims nothing about the original.

| Stop | Where | Kind | Entry condition | Can the caller avoid it? |
| --- | --- | --- | --- | --- |
| QUIT | 0716 at 084D, a call into the credited `0899:0000` (Halt) | non-returning: the process ends | **data**: any directory row the scan visits with packed size > 8CA0h (the test at 080B precedes the id compare at 0855, so rows for other blocks count too) | only by never passing such an archive |
| RUNERROR | IOCheck/GetMem/FreeMem's `JMP 0AF8:00E2` (0716, 06E7, 05CD, 0020, 0000) | non-returning: RunError ends the process | the environment: a failed I/O call, or a heap that cannot satisfy GetMem | no: it depends on DOS and on heap state |
| DIVIDE | BlockRead's recsize-0 DIV | non-returning: INT 0 → RunError 200 | a recsize of 0 | yes, already: 05CD resets with recsize 1, so it is unreachable here |
| STALLED | 050F at 051F | non-returning: a **HANG**, a proven fixed point; nothing ends | **data**: a 7Fh/80h control below the packed size | only by never passing such a block |
| BUDGET | 050F at 051F (`max_arrivals`) | LIMIT | our declared cap | not applicable: says nothing about the original |
| LIMIT | GetMem's free-list walk (`getmem_steps`/`max_steps`) | LIMIT | our declared cap | not applicable |

QUIT and STALLED are both **data-dependent**. Neither is a deliberate exit that a caller chooses; each is the game's response
to archive contents (VP i20345, premise corrected by the decode).

STALLED needs no accounting row; see [RES_0802_050F_CPU.md](RES_0802_050F_CPU.md).

## The re-run with real leaves (VP i20311): done

**The condition attached to #1322 is met.** 0716 has been run with all seven seams composed from the real leaf models, and
with QUIT composed from the credited 0899:0000, against the original run once end to end. The result: **84 of 84 cases
equal** on CPU14, 1 MiB, the file-service state and log, and the environment log, with **0 non-architectural stops**. See
[RES_0802_0716_COMPOSED.md](RES_0802_0716_COMPOSED.md).

**The lesson from its one failed run (two declared keyboard models).** The 0193/ReadKey audits peeked the whole key script
on AH=01h, so every scripted key counted as type-ahead. Under that model, a three-key script meant for two prompts was
consumed entirely by the first one: ReadKey waits for one key and drains the rest. The second prompt then waited on an
empty script, and both the original and the model refused at the same point. The canonical contract keeps type-ahead and
waited keys apart; the peek model is that contract with every key declared type-ahead. Use the canonical contract whenever
more than one wait can happen.

## Identity (the two-factor standard, #1195), proposed for the acceptance

- **Factor 1:** `0802:0716` has overlay callers inside three `game_verified` functions: `OVL_001C_19B0`, `OVL_03BD_0E08` and
  `OVL_03BD_10C7`. It also has game_evidenced callers `03B9_00A2`, `0025_0341` and `006F_0EC4`, and an entry in
  `resident_callable_ledger.csv` (8 overlay far sites, 2 loader sites).
- **Factor 2:** the body reads the game's ECL*.DAX block archives by name and block id into the game's script buffer
  ([ECL_BLOCK_LOAD.md](ECL_BLOCK_LOAD.md)). The 29 real blocks decode byte-exactly above.

The other t30 bodies take identity through this entry plus a per-leaf role line (side i), or join `resident_runtime`
(side ii). That split is recorded in t30.
