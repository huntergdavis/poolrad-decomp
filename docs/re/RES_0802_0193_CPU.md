# Resident 0802:0193, the status-line prompt: raw CPU, composed with ReadKey (t30 display stack, last leaf)

**Summary:** the game's status-line prompt: it shows a message on row 24, waits for a key and blanks row 24, composing the real StrStore, 0175, 0105, 0040, Dos.Intr and ReadKey-with-hotkeys models. Its display evidence covers the **text-mode prompt path only**:
the game's own EGA graphics path is the 0294 EGA device and is **not** exercised here, and a reader must not carry this evidence across to it. **ReadKey may not return** (hotkey `03` with ParamStr `STING` reaches QUIT and exits; Ctrl-Break breaks): then neither does the prompt, and
that is a named stop (`KEY`), not a return.

`pr_r0802_0193` (`src/recovered/resident_0802_0193_cpu.c`) is the raw-CPU, full-state model of START.EXE resident `0802:[0193,01ED)`, the last leaf of the t30 DISPLAY stack in the approved bottom-up order (VP i20338). 025D stops at this entry as its PROMPT seam; 0716's over-limit
prompt calls it too. It composes the merged 0175, 0105, 0040 and ReadKey 0059 models.

**A body and its evidence; no credit is claimed here.** Identity follows the t30 chain ruling, through the role line below.

The audit asserts that the decode covers the span exactly, the single return (`RETF 6` at `01EA`), the five callees (`LCALL 0AF8:0B25` at `01A7`, near `CALL 0175` at `01B9`, near `CALL 0105` at `01CC`, `LCALL 0899:0059` at `01CF`, near `CALL 0175` at `01E4`), that the body is
**straight-line** (no jump, interrupt or port instruction), and that **the two far-call segment words (`01AA`, `01D2`) are the only loader relocations in the span**.

## Behaviour

Arguments: `[SP+4]` the far address of the Pascal message, `[SP+8]` the attribute index (a byte in a word slot).

    0193 PUSH BP; MOV BP,SP; SUB SP,2Ah
    0199 message -> [BP-29h] (StrStore, max 40)                          LCALL 0AF8:0B25
    01AC blank row 24:   0175(column 0, row 18h, attribute 0, count 28h)    PUSH CS; CALL 0175
    01BC write it:       0105(column 0, row 18h, attribute [BP+0Ah], the copy)  PUSH CS; CALL 0105
    01CF wait:           key := 0899:0059; [BP-2Ah] := AL                  LCALL 0899:0059
    01D7 blank row 24 again: 0175(0, 18h, 0, 28h)
    01E7 MOV SP,BP; POP BP; RETF 6

**The prompt path: the message is written, ReadKey waits, row 24 is blanked twice (before and after).** The message is truncated to **40 characters** by StrStore (a 60- or 255-character message writes 40 cells), so, unlike 0105 where the maximum 255 makes StrStore's clamp unreachable, the
clamp **is** reached here (StrStore 16/16 starts). The key ReadKey returns is stored in `[BP-2Ah]` and otherwise unused.

## Callers (asserted)

**no far call, no overlay caller**.

## Composition and contract

- **Composed from their models on main:** StrStore `0B25` (segment word read live from `CS:01AA`), the block filler 0175 twice (displacements from `CS:01BA`, `CS:01E5`), the string writer 0105 (from `CS:01CD`) and ReadKey `0899:0059` (segment word from `CS:01D2`), which itself composes the 08AE driver members, Crt
  ReadKey and KeyPressed (INT 16h), SYSTEM set IN, string compare and ParamStr, and QUIT. Each callee must return to the instruction after its call (else **CALLEE**; **DISPLAY** for 0175/0105).
- **KEY:** ReadKey did not return; the diagnostic carries ReadKey's own status (`EXIT`, `BREAK`, `CRT`, `DRIVER`, `LIMIT`, ...). The second blank never runs.
- **Declared environment:** the display handler (INT 10h through Dos.Intr, `pr_r0802_0040_env`) and ReadKey's environment: INT 21h `25h`/`35h`/`2Ch`, ports, QUIT's INT 10h handler, and **INT 16h as a scripted keyboard**: `AH=01h` reports type-ahead only (ZF set when none) without taking it, `AH=00h` takes type-ahead
  first, else the next scripted key; any other function is refused. This is the same keyboard contract as 025D's.
- Exactly 1 MiB of A20-off RAM, IP = `0193h`, entry SP in `[0190h,FFF0h]`. No flag is masked.

**Role line (t30 side i, argument-borne):** the game's status-line prompt: shows the caller's message on row 24, waits for a key, and clears row 24. Its game state enters through its arguments (the message and the attribute) and through the display and key state of its callees.
