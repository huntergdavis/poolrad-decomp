# Resident 0802:050F, the block decompressor: raw CPU, composed (t30)

`pr_r0802_050f` (`src/recovered/resident_0802_050f_cpu.c`) is the raw-CPU, full-state model of START.EXE resident
`0802:[050F,05CB)`, the RLE decoder that 0716 calls at +0935 on every block it loads. It is the fifth leaf in the approved
order (VP i20316). Its stop site in 0716, DECODE@0935, is the fourth of 0716's seven to have a model.

**A body and its evidence; no credit is claimed here.** Identity follows the t30 chain ruling, through its role line below.

The earlier bounded model `pr_rec_res_0802_050f` ([RESIDENT_DAX_RLE.md](RESIDENT_DAX_RLE.md), issue #82) stays on main
unchanged. It uses host callbacks and does not meet the raw-CPU bar. Its independent trace agrees with this decode on every
point checked: the frame, the unused output-size argument, the signed control ranges, the 7Fh/80h stall, and the size-0
first control.

## Behaviour

    050F PUSH BP; MOV BP,SP; SUB SP,6; in [BP-2] := 0; out [BP-4] := 0
    051F loop: c := packed^[in]             (the packed pointer VARIABLE is reloaded; its offset + in, 16-bit) -> [BP-5]
    0533 c in 00h..7Eh (signed): Move(packed^ + in + 1 -> output^ + out, c + 1); in += c + 2; out += c + 1
    0574 c in 81h..FFh (signed): n := -c; FillChar(output^ + out, n, packed^[in + 1]); in += 2; out += n
         c = 7Fh or 80h: neither path
    05B7 in <u packed-size word (reloaded): JMP 051F; else RETF 10h

- **The frame is four far addresses.** In order they are the packed far-pointer variable `[BP+12h]`, the output far-pointer
  variable `[BP+0Eh]`, the packed-size word `[BP+0Ah]` and the output-size word `[BP+6]`. The output-size word is popped
  but **never read**: there is no output-capacity check.
- **Every pointer is reloaded through its variable on each use.** So output that overwrites a pointer variable or the
  size word changes the rest of the decode. The cases `output-hits-pointer` and `output-hits-size-word` pin this.
- **The first control is read before the size is checked** (a do-while loop): with size 0, one control still runs.
- **Narrow values (instance 6 on the cluster list).** `in`, `out` and every pointer offset are 16-bit and wrap: the output
  index past FFFFh, and the packed and output offsets past FFFFh within their segments. The size test is unsigned (`JAE`).
- **Controls 7Fh and 80h take neither path.** `in` does not move, so with `in` below the packed size the original **never
  returns**. This is the game's own behaviour on a malformed stream, so the model stops with **STALLED** (below). With size
  0 the same control returns after one read.

## The STALLED claim: what carries it

**A proof, not a sample.**

- The decode shows that the iteration taking neither copy path (051F → 0533 → 0574 → 05B7 → 05C2 → 051F) makes exactly one
  memory write, `MOV [BP-5],AL` at 052D, and no pushes.
- The model stops STALLED only after such an iteration in which that write stored the value already there and the 14 CPU
  words at 051F came back identical to the previous arrival's.
- RAM and CPU are then both unchanged, and the next iteration is the same deterministic function of the same state. So the
  state at 051F is a **fixed point**, and the original loops on it forever. The proof assumes no interrupt handler changes
  the bytes the loop reads.
- **Catcher:** the model's equality check plus the decode's single-store fact. The Unicorn differential also compares the
  model's stop state with the original's at the same arrival, in full.
- **Corroboration only:** Unicorn then runs **1,000 further iterations** per stall case, with the CPU identical at every
  arrival and the RAM unchanged at the end (3,000 in all). That is a sample and does not carry the claim; the fixed point
  does.
- **The portable DAX reader cannot corroborate stalls.** It reads 7Fh as a 128-byte literal and 80h as a 128-byte repeat, so
  on these inputs it disagrees with the game by design. It is used as a catcher **on valid data only**.

**Classification (VP i20342): STALLED is an EXIT-class stop, of the HANG kind, not a LIMIT.**

- A LIMIT says that our budget ran out. STALLED says, by the proof above, that **the original never returns**. That is the
  shape of `0899:0000`'s Halt and of ReadKey's BREAK.
- **It differs from them in two ways:**
  - Its entry condition is **data-dependent**: a 7Fh or 80h control below the packed size. It is not a call site.
  - It ends nothing. There is no DOS call, no ExitProc and no INT 23h; the machine simply never leaves 051F–05C2.
- **A caller composing 050F must treat STALLED as terminal.** 0716 can never resume after it, and the game hangs on such a
  block.
- **Accounting:** no row is needed. `RUNTIME_COVERED_TERMINALS` maps runtime-covered SYSTEM endpoints to the declared
  boundaries their stops enter. 050F is a resident 0802 body, and STALLED enters no endpoint. The cluster doc lists it with
  the other non-returning stops.

**BUDGET is not a claim about the original.** Some inputs cycle without a fixed point: a packed size near FFFFh lets `in`
wrap below it. The declared `max_arrivals` bounds the model, which stops at 051F before arrival `max_arrivals + 1`. The
audit compares that state with the original's at the same arrival, and nothing more is claimed.

## Composition and contract

- **Composed:** Move `0AF8:1685` (`system_string_move_leaves_cpu`: offsets-only direction test, a backward copy when the
  source offset is below the destination) and FillChar `0AF8:16A8` (`system_runtime_leaves_cpu`).
- Each far-call segment word is read live from the code. Each callee must return after its call, otherwise the stop is
  **CALLEE**.
- No DOS service and no I/O.
- Stops: RETURNED, STALLED, BUDGET, CALLEE, and ARGUMENT (null pointers, RAM size, IP ≠ 050Fh, or entry SP outside
  `[0016h,FFECh]`; nothing changed).
  - 0016h holds because Move's frame reaches entry SP − 16h.
  - FFECh keeps the `RETF 10h` frame inside the segment.
- Exactly 1 MiB of RAM, with the relocated code at CS. The model executes no code bytes, so a stream that overwrote this
  body's or a callee's code would diverge. No case does: the audit asserts that the
  image range is byte-identical after every case.

**Role line (t30 side i):** expands the game's packed ECL script block, read by 0716 from an ECL*.DAX archive, into the script
buffer that 0716 hands to the interpreter.

## What went wrong in the audit, and what it teaches (VP i20336)

1. **The audit's own oracle hung.** The independent statement was called for the budget case (packed size FFFFh) before the
   case name was checked, and on that input it loops forever. The first full run sat at 100% CPU for 75 minutes with no
   output. **Any loop we write needs a budget, including the loop that checks the loop.** The statement now has its own
   iteration cap (it returns LIMIT), and budget cases skip it.
2. **The audit printed nothing per case,** so the stall could not name itself. It now prints a start line per case, with the
   index, name, C status and arrival count, before Unicorn runs, and a result line after.
3. **The fixture encoded an assumption the hardware does not make.** With SS 6000h and SP 8001h, the stack landed on the
   pointer variables, then at 6800:0000. The original and the C model agreed on that aliased state; only the non-aliasing
   statement disagreed. Moving the variables to segment 8000h fixed the fixture's assumption, not the code. This is the
   night's third stack-aliasing find and the first where the fixture was the culprit.
4. **A `pkill -f` pattern matched my own shell** and killed the timing run (exit 144). A pattern broad enough to kill your
   own process is one keystroke from killing someone else's. Kill by PID, after reading what the PID is.
