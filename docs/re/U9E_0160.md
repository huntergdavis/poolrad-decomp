# Unit 0x9e internal +0x0160 and unit 0x3c6 entries 12-15: bounded model

`src/recovered/overlay_u9e_0160.c` models DOS v1.3 `GAME.OVR` unit `0x9e`
internal routine `+0x0160..+0x02F9`; `src/recovered/overlay_u3c6_slot.c`
translates four small unit `0x3c6` entries it calls. Classification:
**+0x0160 is a bounded model, not strict full C** (unit `0x3c2` entry 6, the
handlers behind the DS table and, optionally, the resident lookup are host
boundaries); **unit `0x3c6` entries 12-15 are full translations** of their
bytes (explicit DS tables as host state; nothing else read or written).
**No count or credit is claimed**; the PM decides after review.

`deja "Poolrad unit 0x9E +0x0160 set constant 0xAF8:0x0DC0"` found no prior
session. Reused with citation: [OVERLAY_UNIT38_EFFECT_ENTRIES.md](OVERLAY_UNIT38_EFFECT_ENTRIES.md)
(the DS:0x6828 table, below), [RESIDENT_SIDECAR_LOOKUP.md](RESIDENT_SIDECAR_LOOKUP.md)
(`pr_rec_res_00ba_2199`, 9-byte sidecar nodes, character `+0x7F` head and
`+0x104` link), [U9E_ENTRY2.md](U9E_ENTRY2.md) (entry 1 dispatcher),
[U7D_ZERO_CALLEE.md](U7D_ZERO_CALLEE.md) (the `member`/`item` host structs),
and GAMEPLAY_PATH.md (the `0xAF8:0x0DC0` set test by argument shape).

## What `+0x0160` does

| Offsets | Effect |
| --- | --- |
| `+0x0167..+0x0199` | `found := 0; cursor := [0x5D96]`; `AL := lookup(B, type, &cell)`; `AL <> 0` -> `found := 1`, jump to `+0x02D4` |
| `+0x019C..+0x01AC` | type not in the set -> `+0x02D4` with `found = 0` |
| `+0x01AF..+0x01BE` | `Move(DS:0x671B, frame, 0xD8)`: save 216 bytes |
| `+0x01C3..+0x01D7` | loop head: cursor nil or `found` -> `+0x02C0` |
| `+0x01DA..+0x01F5` | `AL := lookup(cursor, type, &cell)`; zero -> next member |
| `+0x01F8..+0x01FF`, `+0x02A2` | `[0x49F3] <> 5`: `found := 1` |
| `+0x0202..+0x029E` | `[0x49F3] = 5`: `mode := (type = 0x31) ? 6 : 1`; `0x3C2:entry 6 (e12(cur), e13(cur), mode, 0xFF, e14(cur), far [0x6716]:[0x6718])`; `count := [0x671A]`; `for k := 1 to count: if DS[0x6718 + 3k] = e15(B) then found := 1` |
| `+0x02A7..+0x02BD` | `cursor := cursor + 0x104` (far link); loop |
| `+0x02C0..+0x02CF` | `Move(frame, DS:0x671B, 0xD8)`: restore the same 216 bytes (the far pointer words `0x6716..0x6719` and the count byte `0x671A` are **not** restored) |
| `+0x02D4..+0x02F1` | `found <> 0`: near `+0x0000` (= unit 0x9e entry 1, the DS:0x6828 dispatcher) with `(type, B, cell, 0)`: the handler for `type` is called with the character B, the sidecar node found (`cell`: the last successful lookup's node, which may belong to another party member) and mode **0** |

The save/restore brackets only the party loop: both early exits (found on B
itself, type not in the set) skip it, and nothing is changed there. In the
combat mode (`[0x49F3] = 5`) a party member's node counts only if the scan
(unit `0x3c2` entry 6, not translated) leaves a record whose first byte
equals B's slot number (`entry 15(B)`), otherwise any party member's node
counts. What the nodes, the set and the records mean in game terms is
**not asserted**.

## DS:0x6828 handler table (cited, not re-derived)

OVERLAY_UNIT38_EFFECT_ENTRIES.md decoded the table's installer (unit
`0x38 +0x31A2`, 116 stores of `0x41`-segment stubs) and the dispatcher:
item `(addr - 0x6828) / 4` = the type byte; item 0 is the far-pointer
temporary `[0x6826]/[0x6828]`; sixteen unit `0x38` entries are mapped (items
1, 2, 3, 14, 17, 20, 29, 33, 37, 42, 58, 71, 89, 93, 114, 118), and the
7-byte stub entry 116 fills items 5, 13, 19, 24, 27, 60, 63, 92, 127. The
four set members here (types 21, 45, 46, 49) are **not among those sixteen**,
so their handlers are not identified by that note; the model leaves the
handlers as `pr_u9e_state` hooks. That note's A/B/C frame (A = character
record, B = second far pointer, C = byte) is the `(B, cell, 0)` frame used
here: `(type, A = this routine's B, B = the sidecar node, C = 0)`.
This also corrects U9E_ENTRY2.md's "contents not read": the installer
mapping exists; the individual handlers for most types are still unread.

Each `retf 4` with one far-pointer argument and no trailing data (the next

and `0x5F2A` plus `4 * slot`; slot 0 aliases `[0x5F2A]`, so entry 14 with
an unknown pointer returns the count. The flat `bytes[]` array reproduces
the aliasing.

## Host representation and guards

* Characters are `pr_u7d0_member` (sidecar head `+0x7F`, link `+0x104`);
  sidecar nodes `pr_u7d0_item`. Far pointers compare by identity.
* `scratch[0x306]` is the DS image `0x6716..0x6A1B`; the scan hook receives
  the seven pushed words (`e12, e13, mode, 0xFF, e14`, then offset and
  segment of the far pointer in `[0x6716]:[0x6718]`, read from the scratch)
  and fills the count and records.
* `lookup` defaults to a built-in first-match list search equal to the
  documented semantics of `pr_rec_res_00ba_2199` (byte `+0` equals the key;
  cell = node or nil); it is not re-proved against that translation here.
* A cyclic party list stops after 65,536 steps (`STEP_LIMIT`, span restored).
