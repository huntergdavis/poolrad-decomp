# Second SAVE slot-value dispatch

`pr_second_slot_start` and `pr_second_slot_resume` extend the [second SAVE word and tag branch](U1C_SECOND_SAVE_BRANCH_SHARED_BUS.md) through the existing [SAVE slot-helper entry](U1C_SAVE_SLOT_ENTRY_SHARED_BUS.md), [slot prefix](U25_SLOT_PREFIX_SHARED_BUS.md), and [type dispatch](U25_SLOT_DISPATCH_SHARED_BUS.md), using the same bus and CPU. They stop before the second slot's zero, word, pair, or unmatched body. Earlier first- and second-SAVE outcomes remain distinct, including second operand-string, SAVE-string, and iteration-limit stops. No selected slot body is executed.

Start rejects outer BP below 56 or a nonempty nested branch, loader, SAVE, dispatcher, or runner before mutation. This composition inherits the earlier bounds, independent iteration budgets, and caller responsibilities for code, writes and reached frames. These are bounded assumptions, not a general alias or hardware proof. No original bytes are embedded.

Synthetic integration tests cover the idle-to-Up path through a second numeric SAVE to the pair boundary, a distinct second operand-string stop, and atomic rejection and retry for each nested phase and invalid BP. Existing standalone dispatch tests cover all 256 slot types; the second zero, word and unmatched mappings, second SAVE-string and second-limit mappings are not separately driven by this integration fixture. The wrapper and fixture pass strict-warning ASan/UBSan with the provider archive uninstrumented. This composition has no native differential; selected bodies, further iterations, string execution, movement, visual parity, full gameplay and coverage credit remain unverified.
