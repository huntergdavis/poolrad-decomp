# Unit 3B0 bounded no-key prompt session

`pr_u3b0_prompt_session_start` executes the existing source-bound `+03BD` entry composition. If its nested poll sees no key and the source's `+06CF` epilogue branches to `+048E`, the session yields. `pr_u3b0_prompt_session_resume` executes the real `+048E` wait and single-pass prompt models on the same caller-owned CPU, RAM, EGA and services. An empty poll may yield again; a later FIFO event can reach the existing checked RETF. Setup, label drawing and clocks do not repeat on resume.

The session yields only when the nested wait reports `PASS_LOOP`, the pass reached its return stage, the successful CRT poll remained at its initial `+0566` call site (no key-read calls), and CPU IP is `+048E`. Other branches, including a consumed key that loops, animation, a clock dependency, nested refusal, profile or transfer stop, finish the session as `STOP` with diagnostics and completed effects preserved. `RETURN` only reports the existing model's checked prompt return. It does not set a host `provided` flag or prove native behavior, complete prompt support, entry2 integration, gameplay or credit.

The source's loop is the `CMP [BP-63],0; JNE +06D8; JMP +048E` at `+06CF..+06D7` (9 bytes, SHA-256 `c24571c84c5a3cb61e27a19efc23ad8695b66634c428cae065cb3bad1a954916` in the pinned GAME.OVR); the entry, wait and return evidence and contracts are in [entry setup](U3B0_ENTRY_03BD_DIAGNOSTIC.md), [wait](U3B0_WAIT_048E_DIAGNOSTIC.md), and [return](U3B0_RETURN_06CF_DIAGNOSTIC.md). This is a bounded composition of those models, not an original-runtime or native differential for the new session.

Initialize the caller-owned session before starting. Its entry frame, loaded code and relocation identity, data, bus and all services remain caller-owned under the component contracts. Between a yield and resume, the caller may enqueue an input event through the existing FIFO. It must not mutate the session, CPU, guest RAM, EGA, bus, port configuration or other service state; it must serialize access and keep all objects alive and separate. Resume checks the saved CPU and bus attachment identities before executing and rejects a changed CPU or bus binding without touching guest state. It cannot detect changes to guest RAM, device contents, environment contents or service context; their stability is a caller obligation. Other input sources must obey the same service contracts. No arbitrary-PC or failed-callee resume is offered, and a terminal session cannot resume.

Synthetic tests start from the actual entry frame with real string stores, splitter, clocks, EGA printer/drawer, CRT and FIFO. They exercise an empty start, an empty second tick, unchanged EGA during that tick, later Up and checked return without rerunning clocks, immediate Up, CPU/bus-binding tamper rejection, and a terminal animation stop. The session wrapper and fixture also passed strict-warning ASan/UBSan linked against the existing provider archive. These cases do not validate complete prompt loops or the real host entry2 hook.
