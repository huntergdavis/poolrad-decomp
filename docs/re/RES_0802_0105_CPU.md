# Resident 0802:0105, the status-line string writer: raw CPU, composed (t30 display stack)

**Summary:** the status-line writer, one INT 10h character write per message byte, composing the real StrStore, 0040 and Dos.Intr models. Its display evidence covers the **text-mode prompt path only**: the
game's own EGA graphics path is the 0294 EGA device and is **not** exercised here, and a reader must not carry this evidence across to it.

`pr_r0802_0105` (`src/recovered/resident_0802_0105_cpu.c`) is the raw-CPU, full-state model of START.EXE resident `0802:[0105,0175)`, the second body of the t30 DISPLAY stack (0193 -> 0105/0175 -> 0040) in the approved bottom-up
order (VP i20338). It composes the merged character writer 0040 ([RES_0802_0040_CPU.md](RES_0802_0040_CPU.md)) once per message byte, and SYSTEM StrStore `0B25` once.

**A body and its evidence; no credit is claimed here.** Identity follows the t30 chain ruling, through the role line below.

The audit asserts that the decode covers the span exactly, the single return (`RETF 0Ah` at `0172`), the two callees (`LCALL 0AF8:0B25` at `011B`, near `CALL 0040` at `015F`), no interrupt or port instruction, the

## Behaviour

Arguments: `[SP+4]` the far address of the Pascal message, `[SP+8]` the attribute index, `[SP+0Ah]` the row, `[SP+0Ch]` the first column (each of the last three a byte in a word slot).

    0105 PUSH BP; MOV BP,SP; SUB SP,104h
    010C message -> [BP-100h] (StrStore, max 255)                       LCALL 0AF8:0B25
    0120 n := the copy's length byte; if n = 0 return; i := 1
    0142 repeat  0040(column [BP+0Eh], row [BP+0Ch], attribute [BP+0Ah], count 1, char s[i]);  column := column + 1 (a byte, in place);
         until i = n   (i is a byte, incremented before the test)       PUSH CS; CALL 0040
    016F MOV SP,BP; POP BP; RETF 0Ah

- **One 0040 call per character**, so one cell per call; with `DS:4A1E` = 0 or any value but 1 that is two INT 10h calls per character, with 1 four (see the 0040 document for the three-valued `DS:4A1E`).
- **The column is a byte that wraps at 256:** a message that starts at column `FFh` writes its second character at column 0 (`col-wrap-*` cases).
- **A 255-character message runs 255 iterations** (the index byte is compared after its increment, so the loop does not run away at 255); an empty message skips the loop.
- **The caller's column slot is modified in place** (`INC BYTE [BP+0Eh]`): after the call it holds the starting column plus the length (mod 256).
- **AH at the index load is stale-then-cleared:** the index is loaded with `XOR AH,AH`; after 0040 returns, AH is the high byte of the flags Intr stored, so it is non-zero when IF, DF or OF was set. The `ah-nonzero-flags*` cases pin that, and a mutant that drops the `XOR` is caught only by them.

## Composition and contract

- **Composed from their models on main:** StrStore `0B25` (the far-call segment word read live from `CS:011E`, the offset from `CS:011C`) and the character writer 0040 (the near-call displacement read live from `CS:0160`; 0040 itself composes Dos.Intr four times
  per character). Each callee must return to the instruction after its call (else **CALLEE**); a 0040 call that does not return normally is **DISPLAY**.
- **Declared environment:** the INT 10h handler Intr transfers to (`pr_r0802_0040_env`), exactly as for 0040.
- Stops: RETURNED; DISPLAY (diagnostic: the 0040 status and Intr status, and how many characters completed); CALLEE; ARGUMENT (nothing changed).
- Exactly 1 MiB of A20-off RAM, IP = `0105h`, entry SP in `[0140h,FFF0h]`. No flag is masked.

**StrStore's clamp is unreachable from here.** StrStore's `MOV AL,CL` (the truncation to the maximum) runs only when the source length exceeds the maximum; 0105 passes 255 and a Pascal length byte cannot exceed it. The audit therefore accounts StrStore as 15 of 16 starts and
**asserts that the one start not run is exactly that clamp**.

**Role line (t30 side i, argument-borne):** writes the status-line message supplied by 0193's caller on the display, one character per column from a start column, in an attribute, through INT 10h. Its game state enters through its arguments and through 0040's display operands (`DS:4A1A/4A1B/4A1E`, `DS:25D5`).
