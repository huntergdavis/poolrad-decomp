# Resident 0802:0175, the block filler: raw CPU, composed (t30 display stack, SIDE (ii), NON-CREDIT)

**Summary:** the block filler (the full block `DBh`, `count` times, from a column on one row), a **side (ii) NON-CREDIT** body: **no identity and no credit**. Both call sites push constants, so no game state enters it whatever calls it; it has a model only because 0193 composes it. Its display
evidence covers the **text-mode prompt path only**: the game's own EGA graphics path is the 0294 EGA device and is **not** exercised here, and a reader must not carry this evidence across to it.

`pr_r0802_0175` (`src/recovered/resident_0802_0175_cpu.c`) is the raw-CPU, full-state model of START.EXE resident `0802:[0175,0193)`. In the approved bottom-up order (VP i20338) it sits between 0105 and 0193: 0193 calls it twice (`+01B9`, `+01E4`) and could not compose real bytes until it had a model. It composes
the merged character writer 0040 ([RES_0802_0040_CPU.md](RES_0802_0040_CPU.md)) once.

## Why it is NON-CREDIT (and what that changes)

At **both** call sites, in 0193, the arguments are the constants `0`, `18h`, `0`, `28h`: column 0, row 24, attribute 0, 40 full blocks. A body whose every caller pushes constants takes no game state through its arguments, and it touches the display only through 0040. That is the side (ii) shape (the same shape as
`06FB`, and the file stack's heap wrappers `0000`/`0020`): it gets a model so that a caller can compose it and **gets no identity and no credit**. Appearing in the display chain does not move it: constant arguments mean no game state enters the body, whatever calls it.

**What this change does not do.** The t30 plan notes that the side (ii) bodies need a near-called non-credit resident class, a pricer change and a pinned test, in one PR, because the pricer's near-call walk stops only at declared or strict bodies. That class registration is **separate work and is not done here**: this change adds the body's model and
evidence only, with no registry, ledger, manifest or credit edit.

The audit asserts that the decode covers the span exactly, the single return (`RETF 8` at `0190`), the one callee (`CALL 0040` at `018C`), no jump, far call, interrupt or port instruction, **no loader relocation in the span**, and the constant block character (`MOV AL,DBh` at `0188`).

## Behaviour

Arguments, each a byte in a word slot: `[SP+4]` count, `[SP+6]` attribute, `[SP+8]` row, `[SP+0Ah]` column.

    0175 PUSH BP; MOV BP,SP
    0178 0040(column [BP+0Ch], row [BP+0Ah], attribute [BP+8], count [BP+6], char DBh)        PUSH CS; CALL 0040
    018F POP BP; RETF 8

One 0040 call, so two INT 10h calls with `DS:4A1E` not 1 and four with 1. Each of the five pushed words carries a stale AH (no clear precedes a `PUSH AX`), which the model reproduces and the full-RAM comparison checks. The count is forwarded as 0040's count, so `count` blocks are written from the column on.

## Callers (asserted by the audit's source check and the census)

Census method: segment-wide by construction: every `E8`/`E9` in the 0802 segment whose target is `0175`, every relocated `9A`/`EA` far pattern in the resident image and every overlay segment fixup. Found: **two near calls**, both in 0193 (`+01B9`, `+01E4`); **no far call, no overlay caller**.

## Composition and contract

- **Composed from its model on main:** the character writer 0040 (the near-call displacement read live from `CS:018D`; 0040 composes Dos.Intr). 0040 must return to `018Fh` (else **CALLEE**); a 0040 that stops otherwise is **DISPLAY**.
- **Declared environment:** the INT 10h handler Intr transfers to (`pr_r0802_0040_env`).
- Stops: RETURNED; DISPLAY; CALLEE; ARGUMENT (nothing changed). Exactly 1 MiB of A20-off RAM, IP = `0175h`, entry SP in `[0040h,FFF4h]`. No flag is masked.

## Evidence

Receipt: 2026-10-21, branch from the merged 0105 head on main `1336293f`.

**Unicorn: 377 cases, all RETURNED**, comparing unmasked CPU14 and all 1,048,576 RAM bytes with the whole loader-expanded image at test base `1000` and the loader's relocations applied:

- **closure starts:** 0175 body **16/16**, 0040 **72/72**, Intr **69/69**; no conditional jump in the body; Intr-call histogram: 2 calls in 332 cases, 4 in 45 (`DS:4A1E` = 1);
- **360 cases** whose logged INT 10h blocks equal the independent contract; the other 17 alias the argument slots with Regs or the attribute map, run SP at the bounds, or log counts `15` and `FFFFh`;
- cases: the four `DS:4A1E` values with the `0193` call (`0,24,0,40`); seven attributes x four flag values; **all 256 attribute indices** with `DS:4A1E` = 0; counts `0`, `1`, `2`, `28h`, `4Fh`, `50h`, `FFh`; positions including `FFh` and `25,80`; page pairs; six flag images **and the standing dirty-flag set `0202`, `0602`, `0A87`, `0402`, `0E57`**; random high bytes, Regs, registers and maps.
- **Mutation check:** five deliberate changes are each caught: the constant `DBh` as `DAh`, the column read from `[BP+0Ah]`, the count read from `[BP+8]`, `RETF 6` for `RETF 8`, and a zero-extended argument load in place of the stale-AH one.

**Native DOSBox-X** (packaged `dosbox-x` 2026.01.02, `core=normal`, `cputype=386`; the image relocated to `3000h` and read from `IMAGE.BIN` before every case):

- **Run A, stub level: 26 cases equal.** All 14 CPU words, `[6000:EC00,+400)`, `[3C7C:4A00,+20)` and the log `[2800:0000,+200)` match the C model. **Captured 1,568 bytes per case; the other 1,047,008 bytes of RAM are omitted from the native comparison** (physical ranges `[6EC00,6F000)`, `[411C0,411E0)`, `[28000,28200)`);
  the full-RAM comparison comes from the Unicorn run. The harness does not replay DOS, BIOS, code or capture machinery as identical RAM outside its controlled windows. RESULT.BIN `1c44b19c...4d91`. (The dirty-flag images that set IF are not run natively, where a real timer interrupt would write the stack window.)
- **Run B, BIOS live: 21 cases equal.** No hook; the real BIOS INT 10h in text mode; **344,064 cells compared; 576 non-blank cells written**, every one where the model puts it (the run asserts the written count equals the model's per case and is non-zero for every non-zero count, so an all-blank screen cannot pass).
  Cases: `DS:4A1E` 0, 1, 2 x five (column, row, attribute, count) shapes including a full 80-cell row; five page pairs; a zero count. RESULT.BIN `c3f41a62...7722`. **Captured: 32,784 bytes per case; 1,015,792 bytes of RAM omitted.** The CPU is not compared in run B.
- **Declared substitutions:** run A's INT 10h is a real-byte logging stub; the pinned DOSBox-X source build `5a9c7c53` was not used, and **run B is evidence about the packaged build's BIOS**.
