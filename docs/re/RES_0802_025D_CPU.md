# Resident 0802:025D, open with the "insert disk" loop: raw CPU, composed (t30)

`pr_r0802_025d` (`src/recovered/resident_0802_025d_cpu.c`) is the raw-CPU, full-state model of START.EXE resident
`0802:[025D,02EB)`, the t30 cluster's "find the data file, else ask for the disk" leaf. 05CD calls it at +0659 on every block
load. It is the third leaf in the approved bottom-up order (VP i20316), and its audit carries the required `[557C]` = 0 case:
the insert-disk prompt loop through 0193.

**A body and its evidence; no credit is claimed here.** Identity follows the t30 chain ruling, through its role line below.

## Behaviour

    025D PUSH BP; MOV BP,SP; SUB SP,54h
    0263 name    [BP+10h] -> [BP-2Ah] (StrStore, max 40)
    0276 message [BP+0Ch] -> [BP-53h] (StrStore, max 40)
    0289 loop: [BP-54h] := FileExists(name)            (PUSH CS; CALL 02EB)
    0295   if not found and flag byte [BP+0Ah] = 0:
    02A1     PUSH 0Eh; PUSH message; PUSH CS; CALL 0193 (the prompt; returns by RETF 6)
    02AD   repeat while not found and the flag byte is 0
    02B9 if found: Assign(f = [BP+6], name); Reset(f, 1)
    02DC AL := found; MOV SP,BP; POP BP; RETF 0Eh

- **The flag is a byte.** 05CD pushes it at +064F as `MOV AL,[557C]; PUSH AX`, so the word's high byte is a stale AH. The
  body tests only the low byte. The audit's `flag-high-byte-only` (0100h) and `insert-disk-flag-ff` (FF00h) cases pin this:
  both prompt.
- **With `[557C]` ≠ 0, a missing file returns 0 at once.** There is no prompt, and `f` is not touched.
- **With `[557C]` = 0, the loop does not end until the file exists.** Each pass is one FileExists (open + close), and each
  miss is one prompt. A missing file the player never supplies loops forever, which is the original's behaviour.
- **On success, the file is opened twice.** FileExists opens and closes it, then Reset(f, 1) opens it again, leaving `f` open
  with record size 1 (magic D7B3h).
- **The unit is compiled `{$I-}`.** There is no IOCheck, so FileExists's failure is data, not a terminal stop. This matches
  02EB (see the cluster's `{$I+}`/`{$I-}` note in `RES_0802_0716_CPU.md`).

## Composition and contract

- **Composed from their models on main:**
  - StrStore `0B25` (twice), Assign `13E2` and Reset `1410`, with Reset's nested-Close stop composed as Close, then Reset
    resumed at 1445h;
  - the cluster leaf FileExists 02EB (`pr_r0802_02eb`, #1324), reached by a near `PUSH CS; CALL` and returning by RETF to
    0292h.
- Each far-call segment word is read live from the code. Each callee must return to the instruction after its call, otherwise
  the stop is **CALLEE**.
- **PROMPT is a named stop, not composed.**
  - The model stops at 0193's entry with `[BP+0Ah]`'s caller frame intact. Attribute 0Eh, the message pointer, CS and 02ADh
    are pushed; IP = 0193h.
  - The caller runs the prompt and resumes the model at IP = 02ADh, after 0193's RETF 6.
  - 0193 is the last leaf in the approved order. Composing it is that PR's work.
- **Declared environment:** INT 21h AH=3Dh/3Eh, under the Reset and Close contracts, through `pr_r0802_02eb_env`.
- Stops:
  - **SERVICE:** a declared service declined; CPU at that INT.
  - **CALLEE:** a composed model stopped otherwise, or returned elsewhere.
  - **ARGUMENT:** a precondition below failed; nothing is changed.
- Exactly 1 MiB of RAM. Entry at IP = 025Dh with SP in `[0200h,FFEEh]`, or resume at IP = 02ADh.

**Role line (t30 side i):** opens the game data file named by its caller (05CD's archive path) into the caller's FileRec. When
the game's `[557C]` flag is 0, it asks the player to insert the disk until the file appears.

## Loop budget (2026-10-21)

The retry loop `0289..02B7` is bounded by structure. Each pass either breaks at `02B1` or `02B7`, or stops PROMPT at `02AA`,
so one call or one resume takes at most one `02B7 JE 0289` loop-back. A structural bound is not a budget. A defective model can break the structure, and then the structural argument proves nothing. That is exactly what happened at 0768 (#1357), where a mutant removed the row increment and the model spun for 67 minutes. A budget is the only bound a bug cannot remove (VP i20444, i20463).

`pr_r0802_025d` therefore takes `max_retries`, which counts taken `02B7` loop-backs and is fresh on each entry (`025Dh` or
the `02ADh` resume). The loop-back past the budget stops **LIMIT** with IP `02B7h`, the JE not executed, and diagnostic site
`02B7h`. Each check below names its catcher:

- **Differential.** The audit counts the original's arrivals at `02B7` with ZF set, resets the count at each resume, and
  stops at the same arrival. In `retry-budget-0`, `PROMPT/LIMIT` is equal in CPU14, 1 MiB, file state and the DOS log.
  In `retry-budget-1`, the result is `PROMPT/PROMPT/RETURN`: two resumes, one loop-back each, so the budget is fresh per
  entry on both sides.
- **C test.** `max_retries = 0` on the resume gives LIMIT at `02B7` with ZF set and no second FileExists open.
- **Mutation, the structure broken.** With the `02B1` break deleted, the model loops on a present file. It is caught in
  14 s, at case 2 (`present-flag0`): `C LIMIT original RETURN`. Without the budget it would reopen the file indefinitely.

**A budget stop is not a timeout.** Running past any budget stops LIMIT with nothing of the next step executed. A timeout interrupts the model mid-step and leaves the state half-changed; a budget stop leaves it at a boundary, where the audit can compare it with the original stopped at the same arrival (VP i20511).

**Fresh per entry, not cumulative.** Every budget restarts at each entry and at each resume after a named stop, so it bounds one pass through the loop rather than the whole run. Do not assume a counter is cumulative: the 025D audit proves the property with budget 0 (`retry-budget-0`, PROMPT/LIMIT) and budget 1 (`retry-budget-1`, PROMPT/PROMPT/RETURN, two resumes taking one loop-back each). A cumulative count would stop the second case LIMIT.
