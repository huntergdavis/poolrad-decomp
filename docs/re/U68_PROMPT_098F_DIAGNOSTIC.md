# U68 shared-bus prompt prefix and Up continuation

`pr_u68_prompt_start` starts at a caller-supplied live unit 68 `+098F` frame. It reads window 1 through DS:`49D6`, clears its `+0592` word through the shared bus, reads the live selector, and takes only selector 1. It copies caller-owned private `CS:097A` to `SS:[BP-33]` with the real SYSTEM `0B0B` model, pushes the source's DS:`04B6` menu, five controls and `SS:[BP-4]` output pointer, then enters the actual loaded `03C5:002A` far-jump stub to unit 3B0 `+03BD`. The existing prompt session can yield at its verified idle loop; `pr_u68_prompt_resume` continues that session without repeating the window clear, string copy or clocks.

On a checked prompt return to U68 `+09D5`, the wrapper stores returned AL at `[BP-3]`, reads the live by-reference `[BP-4]` flag, and follows only extended Up (`AL=48h`). It executes the real `+068D` Up preflight, including the loaded unit 3BD `+0350` model, writes `[BP-2]=1`, and stops at `+0B9B` **before** the unresolved resident `00BA:290B` display call. Non-selector-1, nonextended or non-Up paths stop at their source branch destinations. `DISPLAY` does not mean that the display call, gameplay or entry2 return occurred.

This wrapper starts after the source prologue at `+098F`. Prior shared-memory recall worker2 session `01a12b3e` identified `03C5:002A` as the prompt call; the stub-to-entry binding is also documented in [U25 entry 13](U25_ENTRY13_1684.md). Call opcodes/offsets and live segment words are checked at reached sites; an unloaded prompt stub stops with its far frame intact. No private bytes are included.

Entry requires exactly 1 MiB RAM and an attached EGA, IP `098F`, `BP-SP=3Ch`, BP `[0090,FFE3]`, SP `[01EC,FFFC]`, CS/DS/SS below `9000` or at least `B000`, and prompt environment return target equal to this U68 CS:`09D5`. The caller owns the real frame, source title and menu data, loaded code, stubs, segment relocations, device state and all services. The window is bus-backed, including EGA. When the initial word's effective offset is `FFFF`, the wrapper stops before the word write as an unsupported profile. SYSTEM `0B0B` uses flat RAM; the ordinary CS/SS windows bound its source, destination and frame. Existing prompt-session and nested component contracts remain mandatory, including caller ownership and no guest RAM/device/service mutation across an idle yield except FIFO enqueue.

The Up preflight uses flat-RAM code/stack/global and field-lookup operations. Before calling it, the wrapper requires an ordinary loaded-stub segment and an ordinary live map-buffer segment, and refuses if the potential preflight stack footprint aliases either the map-buffer or window far-pointer storage, or if the first window-word write aliases map-buffer pointer storage. Its window writes still go through the bus. This is a conservative supported profile, not a blanket alias proof; loaded instructions and bindings must remain immutable and host callbacks must not mutate guest state. Raw preflight `OVERLAY`, callee and transfer stops retain prior effects and are reported in diagnostics. A malformed call or unloaded stub likewise retains earlier writes and pushes. Invalid initial arguments are atomic; `ARGUMENT` on a changed suspended CPU/bus leaves the yielded session available after the caller restores the binding. Other stops are terminal.
